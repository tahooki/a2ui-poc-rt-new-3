# A2UI PoC 발표 스크립트

> 발표 형식: 스토리텔링 → 기존 시연 → 페인포인트 → A2UI 소개 → A2UI 시연
> 예상 소요: 15~20분

---

## 오프닝

> 안녕하세요. 오늘은 DevOps 콘솔에 적용한 A2UI PoC를 소개드리려 합니다.
> 기능 설명부터 시작하는 대신, 실제로 이 콘솔을 쓰는 세 사람의 이야기를 먼저 들려드리겠습니다.

---

---

## Part 1. 배포 (Deploy)

---

### 1-1. 스토리텔링 + 이미지

> **[이미지: 모니터 앞에 앉아 콘솔을 보는 엔지니어]**
>
> 김배포 선임은 Platform Engineer입니다.
> 매일 아침 9시에 출근하면 가장 먼저 하는 일이 있습니다.
> 어제 배포한 서비스들이 잘 돌아가고 있는지 확인하고,
> 오늘 예정된 배포를 준비하는 겁니다.
>
> 서비스가 12개, 환경이 3개.
> 이력을 보려면 페이지를 이동하고, 필터를 걸고, 스크롤을 내려야 합니다.
> 배포를 시작하려면 드롭다운을 열고, 버전을 고르고, preflight check을 돌리고,
> 최종 확인 버튼을 눌러야 합니다.
>
> **[이미지: 복잡한 배포 콘솔 화면 — 여러 드롭다운, 필터, 테이블]**
>
> 하나의 배포를 시작하기까지 최소 7단계.
> "payments-api 마지막 배포가 언제였지?" 이 한 가지를 알기 위해 3분.
>
> 김배포 선임의 하루는 이런 클릭의 반복으로 채워집니다.

---

### 1-2. 기존 Admin 시연

> 그러면 실제로 김배포 선임이 하는 작업을 한번 해보겠습니다.

**[기존 콘솔 라이브 시연]**

- 배포 이력 페이지 진입
- 서비스 필터 선택 → payments-api
- 날짜 범위 조정
- 마지막 배포 정보 확인
- 다시 배포 페이지로 이동
- 서비스 선택 → 버전 선택 → preflight check → 배포 시작

**시연 중 강조 포인트:**
- 페이지 이동 횟수 (최소 2~3회)
- 클릭 횟수 (최소 7~8회)
- 정보 확인을 위한 컨텍스트 스위칭

---

### 1-3. 페인포인트 정리

> 보셨듯이, 단순한 작업인데도 꽤 많은 단계를 거칩니다.
>
> **[이미지: 페인포인트 요약 카드]**
>
> - **이력 확인에 3분** — 페이지 이동, 필터 설정, 스크롤
> - **배포 시작까지 7단계** — 드롭다운, 선택, 확인의 반복
> - **배포 전략이 헷갈릴 때** — 콘솔을 떠나 위키를 검색해야 함
> - **서비스를 잘못 골랐을 때** — 뒤로 가기 → 처음부터 다시
>
> 김배포 선임은 매일 이런 과정을 2~3회 반복합니다.
> 클릭이 아니라 **배포 자체에 집중**할 수 있으면 좋겠다고 늘 생각합니다.

---

### 1-4. A2UI 소개

> 이 문제를 A2UI로 풀어냈습니다.
>
> A2UI — Adaptive Agentic User Interface.
> 사용자의 자연어 입력을 이해하고, 필요한 데이터를 조회하고,
> 적절한 UI Surface를 동적으로 렌더링하는 방식입니다.
>
> **[이미지: 기존 흐름 vs A2UI 흐름 비교 다이어그램]**
>
> | 기존 | A2UI |
> |------|------|
> | 이력 확인 → 페이지 이동 + 필터 | "마지막 배포 언제?" → 즉시 응답 |
> | 배포 시작 → 7단계 클릭 | "payments-api 배포해줘" → 1턴 |
> | 전략 확인 → 위키 검색 | "rolling이랑 blue-green 차이?" → 즉시 답변 |
> | 실수 정정 → 뒤로 가기 | "아니 다른 걸로" → 즉시 정정 |

---

### 1-5. A2UI 시연

> 오늘 마침, NFX 팀에서 챗봇에 Deploy A2UI를 추가해줬다고 합니다.
> 한번 열어보겠습니다.

**[챗봇 패널 오픈]**

**시연 시나리오:**

```
👤 "payments-api 마지막 배포 언제였어?"
   → AI가 이력 조회 후 텍스트로 응답

👤 "배포하고 싶어"
   → 서비스 선택 칩 표시: [payments-api] [checkout] [catalog-api]

👤 "payments-api"
   → Quick Deploy Launchpad Surface 렌더링

👤 [배포 시작] 클릭
   → 배포 애니메이션 → 완료
```

**추가 시연 (여유 있을 경우):**

```
👤 "rolling 배포랑 blue-green 차이가 뭐야?"
   → 작업 화면 떠나지 않고 즉시 답변

👤 (서비스 선택 중) "아니 checkout"
   → 즉시 정정

👤 "취소해줘"
   → 흐름 취소 후 대기
```

> 김배포 선임의 7단계가 대화 2턴으로 줄었습니다.
> 3분이 걸리던 이력 확인이 3초가 됐습니다.

## Part 2. 승인 (Approval)

---

### 2-1. 스토리텔링 + 이미지

> **[이미지: 회의실에서 나오며 노트북을 여는 팀장]**
>
> 이승인 팀장은 DevOps Team Lead입니다.
> 오후 미팅이 끝나면 가장 먼저 승인 큐를 확인합니다.
>
> "지금 대기가 몇 건이지?"
> "config change는 별도로 있나?"
> "고위험 요청이 섞여 있진 않은가?"
>
> **[이미지: 승인 큐 페이지 — pending 필터, 유형별 분류가 없는 긴 리스트]**
>
> 세 가지 질문에 답하려면 필터를 세 번 바꿔야 합니다.
> 고위험 요청은 리스트를 눈으로 하나씩 훑어야 찾을 수 있습니다.
>
> 승인은 빠르게 처리해야 하는 업무입니다.
> 요청자는 승인이 나야 다음 작업을 진행할 수 있으니까요.
> 그런데 "현황 파악"에만 시간이 걸립니다.

---

### 2-2. 기존 Admin 시연

> 이승인 팀장의 승인 업무를 직접 해보겠습니다.

**[기존 콘솔 라이브 시연]**

- 승인 페이지 진입
- 필터: pending → 건수 확인
- 필터: config change → 해당 건 확인
- 리스트에서 고위험 표시 찾기 (눈으로 스캔)
- 개별 요청 클릭 → 상세 확인 → 승인 또는 보류

**시연 중 강조 포인트:**
- 전체 현황을 알기 위한 필터 변경 횟수
- 고위험 요청을 놓칠 수 있는 가능성
- 개별 요청마다 상세 페이지 진입 필요

---

### 2-3. 페인포인트 정리

> **[이미지: 페인포인트 요약 카드]**
>
> - **현황 파악에 필터 3번 변경** — 유형별, 상태별, 위험도별
> - **고위험 요청 놓칠 위험** — 리스트에 시각적 우선순위가 약함
> - **승인 판단에 필요한 정보 부족** — "보류하면 어떻게 되지?" 같은 질문에 즉시 답을 얻을 수 없음
> - **승인 중 다른 도메인 작업 필요 시** — 탭 전환 → 컨텍스트 유실
>
> 승인은 "속도"가 중요한 업무인데,
> 정작 "판단"이 아닌 "탐색"에 시간을 쓰고 있습니다.

---

### 2-4. A2UI 소개

> 승인 도메인에서도 A2UI를 적용했습니다.
>
> **[이미지: 기존 흐름 vs A2UI 흐름 비교]**
>
> | 기존 | A2UI |
> |------|------|
> | 현황 파악 → 필터 3번 | "대기 몇 건?" → 유형별 요약 + 고위험 알림 |
> | 개별 요청 확인 → 페이지 진입 | "승인 요청 확인해줘" → 큐 Surface 즉시 렌더링 |
> | 판단 기준 확인 → 별도 문서 | "고위험 처리 어떻게?" → 즉시 가이드 |
> | 도메인 전환 → 탭 이동 | "배포하고 싶어" → 대화 내 즉시 전환 |

---

### 2-5. A2UI 시연

> NFX 팀에서 Approval A2UI도 함께 추가해줬습니다.
> 챗봇에서 바로 해보겠습니다.

**[챗봇 패널에서 이어서 시연]**

**시연 시나리오:**

```
👤 "지금 승인 대기 몇 건이야?"
   → 유형별 건수 + 고위험 건수 요약 텍스트 응답

👤 "승인 요청 확인해줘"
   → Approval Queue Inbox Surface 렌더링
   → 고위험 요청이 상단에 강조 표시

👤 [승인] 클릭
   → 승인 완료 애니메이션

👤 [보류] 클릭
   → 보류 처리 애니메이션
```

**추가 시연 (여유 있을 경우):**

```
👤 "보류하면 어떻게 돼?"
   → 보류 프로세스 즉시 설명

👤 "고위험 요청은 어떻게 처리해?"
   → 처리 가이드 즉시 응답

👤 (승인 처리 중) "롤백하고 싶어"
   → 롤백 도메인으로 자연스러운 전환
```

> 필터를 3번 바꾸던 것이 질문 1번으로 바뀌었습니다.
> 고위험 요청은 AI가 먼저 알려줍니다.

## Part 3. 롤백 (Rollback)

---

### 3-1. 스토리텔링 + 이미지

> **[이미지: 어두운 방에서 노트북 불빛에 비친 얼굴 — 새벽 알림]**
>
> 박롤백 대리는 SRE입니다.
> 새벽 2시, PagerDuty 알림이 울립니다.
>
> `payments-api — severity HIGH — error rate spike`
>
> 잠에서 깬 그가 가장 먼저 알아야 할 것:
> - 지금 어떤 서비스에서 문제가 생겼는가?
> - 인시던트 심각도는?
> - 롤백 가능한 버전이 있는가?
> - 롤백하면 데이터는 안전한가?
>
> **[이미지: 여러 탭이 열린 모니터 — 모니터링, 인시던트, 콘솔, 위키]**
>
> 기존에는 이 답을 얻기 위해 4개의 화면을 동시에 열어야 했습니다.
> 모니터링 대시보드에서 에러율 확인,
> 인시던트 페이지에서 상세 내역 확인,
> 콘솔에서 롤백 가능 버전 확인,
> 위키에서 롤백 절차 확인.
>
> 새벽에, 잠이 덜 깬 상태에서, **최소 5분.**
>
> 인시던트 대응에서 가장 중요한 건 속도입니다.
> 그런데 "실행"이 아닌 "정보 수집"에 시간이 빠져나가고 있습니다.

---

### 3-2. 기존 Admin 시연

> 박롤백 대리가 새벽에 하는 작업을 재현해 보겠습니다.

**[기존 콘솔 라이브 시연]**

- 인시던트 페이지 확인 → severity, 영향 서비스
- 롤백 페이지로 이동
- 서비스 필터 → payments-api
- 버전 목록 확인 → 어떤 버전이 stable인지 판단
- dry run 실행 여부 고민 → 위키에서 절차 확인
- 롤백 실행

**시연 중 강조 포인트:**
- 4개 화면을 오가는 컨텍스트 스위칭
- 긴박한 상황에서의 인지 부하
- "이 버전이 맞나?" 확신 없이 클릭하는 불안감

---

### 3-3. 페인포인트 정리

> **[이미지: 페인포인트 요약 카드]**
>
> - **정보 수집에 5분** — 4개 화면을 오가며 상황 파악
> - **추천 버전 없음** — 어떤 버전으로 롤백해야 하는지 스스로 판단해야 함
> - **절차 확인 불가** — "dry run이 뭐였지?" "데이터는 괜찮나?" → 위키 검색
> - **새벽의 인지 부하** — 잠이 덜 깬 상태에서 여러 화면, 여러 판단
>
> 인시던트 대응은 분 단위가 아니라 **초 단위**입니다.
> 5분은 너무 긴 시간입니다.

---

### 3-4. A2UI 소개

> 롤백은 A2UI의 가치가 가장 극명하게 드러나는 도메인입니다.
>
> **[이미지: 기존 흐름 vs A2UI 흐름 비교]**
>
> | 기존 | A2UI |
> |------|------|
> | 상황 파악 → 4개 화면 동시 | "롤백 상태 알려줘" → 인시던트 + 추천 버전 한번에 |
> | 버전 선택 → 본인 판단 | AI가 추천 버전 제시 |
> | 절차 확인 → 위키 검색 | "dry run이 뭐야?" → 즉시 설명 |
> | 실행까지 5분 | **대화 2턴, 30초** |

---

### 3-5. A2UI 시연

> Rollback A2UI도 준비되어 있습니다.
> 새벽 2시 상황이라고 생각하고 해보겠습니다.

**[챗봇 패널에서 이어서 시연]**

**시연 시나리오:**

```
👤 "payments-api 롤백 상태 알려줘"
   → 현재 버전 + 인시던트 정보 + 추천 롤백 버전 텍스트 응답

👤 "롤백하고 싶어"
   → 서비스 선택 칩: [payments-api] [checkout] [catalog-api]

👤 "payments-api"
   → Rollback Target List Surface 렌더링
   → v2.3.16 (stable, 추천) / v2.3.15 (stable)

👤 [이 버전으로 롤백] 클릭
   → rolling back 애니메이션 → recovered
```

**추가 시연 (여유 있을 경우):**

```
👤 "롤백하면 데이터는 어떻게 돼?"
   → DB 마이그레이션 관련 즉시 설명

👤 "롤백 실패하면 어떻게 해?"
   → 다음 행동 가이드 즉시 응답

👤 (롤백 완료 후) "배포하고 싶어"
   → 배포 도메인으로 자연스러운 전환
```

> 4개 화면을 오가던 것이 대화 한 곳에서 끝납니다.
> 새벽에 위키를 뒤지지 않아도 됩니다.
> 5분이 30초가 됩니다.

## Part 4. 도메인 전환 시연 (보너스)

> 지금까지 배포, 승인, 롤백을 각각 보여드렸는데,
> 현실에서는 이 세 가지가 동시에 일어납니다.
>
> 배포하다가 승인이 필요하고,
> 승인하다가 롤백 상황을 발견하고,
> 롤백 후에 재배포가 필요합니다.
>
> 기존에는 탭을 전환하면 작업 컨텍스트가 사라졌습니다.
> A2UI에서는?

**[챗봇 패널에서 이어서 시연]**

```
👤 (배포 진행 중) "승인 요청 확인해줘"
   → 자연스럽게 Approval Queue Surface 전환

👤 (승인 처리 중) "롤백 후보 알려줘"
   → 자연스럽게 롤백 상태 응답

👤 (롤백 완료 후) "배포하고 싶어"
   → 자연스럽게 배포 흐름 시작
```

> **탭 전환도, 페이지 이동도 없습니다.**
> **대화의 흐름 안에서 모든 도메인을 넘나듭니다.**

>
> 72개 시나리오를 기반으로 실제 DevOps 워크플로우의
