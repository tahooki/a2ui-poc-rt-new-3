A2UI PoC Developer Guide

Admin에서 조립하고, Agent가 판단하고, Chatbot이 렌더하는 A2UI 가이드

이 문서는 현재 PoC에서 작업된 내용을 한 페이지로 설명합니다. 프론트 컴포넌트 작성부터 Admin 구성, Python agent 연동, 기존 chatbot에 끼워 넣는 방식까지 개발자가 따라갈 수 있게 정리했습니다.

Step 1

초안

처음 설명은 전체 구현을 기능 단위로 짧게 요약하는 데 집중했습니다.

이번 작업은 배포용 A2UI 컴포넌트를 Admin에서 구성하고, 사용자가 "배포하고싶어"라고 말하면 chatbot 안에서 해당 surface가 렌더되도록 만드는 PoC입니다.

프론트에서는 A2UI part를 만들고, Admin은 part manifest를 읽어서 surfaceConfig를 편집합니다. Agent는 React 컴포넌트를 알 필요 없이 payload, actions, surfaceConfig가 들어간 surface envelope만 반환합니다.

Chatbot은 새로 만든 @a2ui/chat의 A2UISurfaceHost를 메시지 렌더러에 꽂아서 surface를 표시하고 action을 adapter로 실행합니다.

Step 2

이해를 돕기 위한 보완 포인트

초안만으로는 "그래서 개발자는 어디를 열어 무엇을 해야 하는가"가 부족해서 아래 관점으로 다시 구성했습니다.

역할을 분리해서 설명

프론트, Admin, MCP/template store, Python agent, chatbot host를 각각 다른 책임으로 나눴습니다.

파일 경로를 기준으로 안내

추상 설명보다 실제 개발자가 열 파일과 import할 API를 먼저 보여줍니다.

실제 동작과 PoC 범위 구분

구조는 작동하지만 실배포 API 데이터는 mock이라는 점을 분명히 나눴습니다.

Admin preview의 안전성 표시

read-only preview에서는 action이 disabled 처리되어 confirm이나 실행 경로가 열리지 않는다는 점을 포함했습니다.

외부 chatbot 통합 관점 추가

운영 chatbot이 하나의 exact schema를 강제하지 않도록 surface normalization 경계를 설명했습니다.

개발 순서 제공

새 part 추가 시 컴포넌트, registry, manifest, binder, agent, chatbot 순서로 따라갈 수 있게 했습니다.

Step 3

최종 가이드: 지금 만들어진 구조

핵심은 "React 컴포넌트를 Admin이나 Python에 직접 공유하지 않는다"입니다. 대신 part definition manifest와 surface envelope라는 계약을 공유합니다.

2. Renderer registry 등록

surfaceConfig의 type이 실제 React component를 찾을 수 있게 연결합니다.

packages/a2ui-ui/src/dynamic/part-registry.ts DeployArtifactBlock, DeployTargetSummaryBlock 같은 type/component mapping 
export function DeployArtifactBlock(props: Record<string, unknown>) {
  const image = isRecord(props.image) ? props.image : null;
  const visibleFields = Array.isArray(props.visibleFields)
    ? props.visibleFields.filter((field): field is string => typeof field === "string")
    : DEFAULT_FIELDS;

  return (
    <PartSection subtitle="Selected deploy artifact from the service context." title="Image artifact">
      {image ? (
        <DataTable
          columns={[{ key: "field", label: "Field" }, { key: "value", label: "Value" }]}
          rows={visibleFields.map((field) => ({
            fieldKey: field,
            field: FIELD_LABELS[field] ?? field,
            value: image[field],
          }))}
        />
      ) : (
        <EmptyPartState label="No image artifact selected" />
      )}
    </PartSection>
  );
}

Surface Envelope

Agent와 Chatbot 사이의 데이터 계약

Agent는 React를 몰라도 됩니다. 아래 형태의 surface envelope만 반환하면 됩니다.

{
  "templateId": "quick_deploy_launchpad",
  "payload": {
    "service": "payments-api",
    "environment": "production",
    "targetVersion": "v2.3.18-rc1",
    "imageDetail": {
      "repository": "payments-api",
      "imageTag": "v2.3.18-rc1"
    }
  },
  "actions": [
    {
      "actionId": "deploy.start",
      "label": "배포 시작",
      "variant": "primary"
    }
  ],
  "surfaceConfig": {
    "kind": "a2ui_card",
    "parts": [
      { "id": "deploy-artifact", "type": "DeployArtifactBlock", "props": {} }
    ]
  }
}

payload

실제 데이터입니다. Admin에서 설정한 binding path가 여기 값을 읽습니다.

surfaceConfig

어떤 card shell과 part 조합으로 보여줄지 정의합니다.

actions

버튼과 action event를 정의합니다. 실행은 chatbot host의 adapter가 맡습니다.

Agent

Python agent에는 무엇을 넣나

Python agent는 UI 컴포넌트를 import하지 않습니다. MCP를 호출해서 surface envelope를 받아 응답에 포함합니다.

Python MCP client

a2ui.recommendTemplate와 a2ui.resolveTemplateData를 호출합니다.

packages/demo-agent-server/app/a2ui_agent.py render_or_fallback, handle_action

대화 orchestration

intent와 facts를 판단한 뒤 render_or_fallback을 호출합니다.

packages/demo-agent-server/app/orchestrate.py 8-step pipeline, ChatResponse.surface 
from .a2ui_agent import render_or_fallback

a2ui_result = await render_or_fallback(
    intent_key=intent_result.intent_key,
    facts=facts,
)

if a2ui_result.type == "surface":
    surface = a2ui_result.surface
    text = "배포 런치패드를 준비했습니다."
Chatbot Integration

기존 운영 chatbot에는 어떻게 끼우나

운영 chatbot 전체를 바꾸는 게 아니라, message renderer나 attachment slot에 A2UISurfaceHost를 넣습니다.

공용 host

surface 정규화, renderer 호출, action 상태 표시, action 결과 반영을 담당합니다.

packages/a2ui-chat/src/A2UISurfaceHost.tsx 기존 chatbot에 꽂는 핵심 host packages/a2ui-chat/src/types.ts A2UISurfaceActionAdapter, status, message part type

PoC action adapter

PoC 앱에서는 action bridge와 post-action refresh를 adapter 안에 숨겼습니다.

src/devops-chat/integrations/a2ui-surface-action-adapter.ts executePocA2UISurfaceAction examples/a2ui-chatbot-embed/GenericChatMessage.tsx 외부 chatbot embed 예제 
import {
  A2UIMessageSurface,
  createA2UIChatSurfacePart,
  type A2UISurfaceActionAdapter,
  type A2UIRenderableSurface,
} from "@a2ui/chat";

export type GenericChatMessage = {
  id: string;
  role: "user" | "assistant" | "tool";
  text?: string;
  surface?: A2UIRenderableSurface;
};

export function GenericChatMessageView({
  message,
  onSurfaceAction,
}: {
  message: GenericChatMessage;
  onSurfaceAction: A2UISurfaceActionAdapter;
}) {
  const part = message.surface
    ? createA2UIChatSurfacePart(message.surface, `${message.id}-surface`)
    : null;

  return (
    <article>
      <p>{message.text}</p>
      {part ? <A2UIMessageSurface part={part} onAction={onSurfaceAction} /> : null}
    </article>
  );
}
Review 반영: A2UISurfaceActionResult.surface는 unknown | null을 받을 수 있습니다. 운영 chatbot이 PoC와 같은 exact schema를 쓰지 않아도 host가 normalization boundary에서 정리합니다.
