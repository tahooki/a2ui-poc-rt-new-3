API Generator Parser scripts/api-generator — Montage Design System

빌드 타임에 .tsx 소스 파일을 읽어 React 컴포넌트의 Props 타입 정보를 JSON으로 추출하는 파서입니다. ts-morph를 사용해 TypeScript AST를 분석합니다.

한눈에 이해하기

기술적인 내용에 앞서, 이 파서가 왜 필요하고, 무엇을 하는지 쉽게 풀어서 설명합니다.

비유로 이해하기

레고 블록 세트를 생각해보세요. 각 블록(= 컴포넌트)에는 설명서가 있어서 "이 블록은 빨간색이고, 2x4 크기이고, 위에 다른 블록을 꽂을 수 있다"고 적혀 있죠.

이 파서는 레고 블록의 설명서를 자동으로 만들어주는 기계입니다. 개발자가 TypeScript로 작성한 컴포넌트 코드를 읽어서, "이 컴포넌트는 size, variant, disabled 같은 설정값(props)을 받을 수 있고, 각각의 타입은 이렇다"는 정보를 자동으로 뽑아냅니다.

왜 필요한가요?

디자인 시스템의 문서 사이트에서 각 컴포넌트의 Props 테이블을 보여줘야 합니다. 이걸 사람이 수동으로 관리하면 코드와 문서가 어긋나기 쉽죠. 파서가 코드에서 직접 추출하므로 항상 최신 상태를 유지할 수 있습니다.

자주 묻는 질문

왜 정규식 대신 ts-morph를 쓰나요?
정규식으로는 forwardRef, 제네릭, 타입 상속 같은 복잡한 TypeScript 패턴을 정확히 파싱할 수 없습니다. ts-morph는 TypeScript 컴파일러 위에서 동작하기 때문에 실제 타입 체커가 보는 것과 동일한 정보를 얻을 수 있습니다.
onClick 같은 HTML 이벤트 핸들러는 왜 안 나오나요?
onClick, className 등은 @types/react에서 오는 기본 props입니다. 파서는 선언 파일 경로를 확인해서 React 내장 props를 자동으로 제외하고, 개발자가 직접 정의한 props만 추출합니다.
새 컴포넌트를 만들면 자동으로 추출되나요?
네! packages/wds/src/components/ 하위에 .tsx 파일을 만들고 PascalCase 이름으로 export하면, 다음 pnpm build:api 실행 시 자동으로 포함됩니다. 별도의 설정 파일 수정은 필요 없습니다.
기본값은 어디서 가져오나요?
컴포넌트 함수의 파라미터 구조분해에서 가져옵니다.
예: ({ size = 'medium' }) → defaultValue: "\"medium\""
타입 선언의 JSDoc이 아닌, 실제 런타임 기본값을 읽습니다.
타입이 너무 복잡하면 어떻게 되나요?
제네릭이 3단계 이상 중첩되면 더 이상 풀지 않고, import 경로만 정리한 원본 텍스트를 그대로 사용합니다. 무한 루프를 방지하기 위한 안전장치입니다.

6-2. 각 Resolver의 변환 규칙

Resolver입력 예시출력 예시비고
resolvePrimitive string, boolean, 42, "hello" string, boolean, 42, "hello" 리터럴 타입 포함
resolveUnion string | number | undefined string | number undefined 제거, true|false → boolean
resolveIntersection A & B A & B 각 멤버 재귀 resolve
resolveArray string[], (A | B)[] string[], Array<A | B> 복합 타입은 Array<T> 형태
resolveTuple [string, number] [string, number]
resolveFunction (e: Event) => void (e: Event) => void callSignature 기반
resolveObject { x: number; y?: string } { x: number; y?: string } 10개 이하 프로퍼티만 인라인
resolveAlias Record<string, number> Record<string, number> aliasSymbol + typeArgs
resolveSymbol Map<string, number> Map<string, number> symbol + typeArgs

6-3. Preserved Types

다음 타입들은 resolve하지 않고 이름 그대로 보존합니다:

ReactNode · ReactElement · ReactFragment · ReactPortal · JSX.Element · CSSProperties · RefObject · MutableRefObject · Ref · ForwardedRef · CSSInterpolation · SxProp · ThemeColorsToken

10. 주요 설계 결정

재귀 깊이 제한 (depth ≤ 2)

React 내장 props 제외
onClick, className 등 @types/react에서 오는 props는 선언 파일 경로(node_modules/@types/react)를 확인하여 자동 제외합니다. 사용자가 커스텀 정의한 동일 이름의 prop은 포함됩니다.
Union에서 undefined 제거
optional prop의 타입에서 undefined를 제거하여 string | undefined 대신 string으로 표시합니다. true | false는 boolean으로 통합됩니다.
