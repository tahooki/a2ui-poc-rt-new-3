React Props Parser lib/ — 어떤 React 프로젝트에든 붙여 쓸 수 있는 컴포넌트 Props 추출 라이브러리

한눈에 보기

.tsx 파일을 읽어서 React 컴포넌트의 Props 타입 정보를 JSON으로 추출합니다.
TypeScript 컴파일러(ts-morph) 기반이라 정규식보다 정확하고, 옵션으로 동작을 조절할 수 있어서 어떤 프로젝트에든 이식 가능합니다.

최소 코드

import { Parser } from './lib';

const parser = new Parser('./tsconfig.json');

const items = parser.getExportedItems();       // PascalCase export 수집
const result = parser.parse(items);             // Props 추출

console.log(JSON.stringify(result, null, 2));  // ComponentInfo[]

이게 전부입니다. 옵션 없이도 동작하며, 대부분의 React 컴포넌트 패턴을 자동 인식합니다.

옵션 주입 흐름

new Parser(tsconfig, options?) 하나로 모든 설정이 전달됩니다. 내부에서 옵션이 어떻게 흘러가는지 보여드립니다. 

sequenceDiagram
  participant User as 사용자 코드
  participant P as Parser
  participant E as Extractor
  participant R as Resolver

  User->>P: new Parser(tsconfig, options)
  Note over P: options.resolver,
options.extractor 분리

  P->>E: new Extractor(resolverOpts, extractorOpts)
  Note over E: rawTypeProps,
complexAnnotationTypes 저장

  E->>R: new Resolver(resolverOpts)
  Note over R: preservedTypes,
typeParameterMap,
maxDepth 저장

옵션 레퍼런스

ParserOptions

최상위 옵션. resolver와 extractor 두 그룹으로 나뉩니다.

const parser = new Parser('tsconfig.json', {
  resolver:  { /* ResolverOptions */ },
  extractor: { /* ExtractorOptions */ },
});

ResolverOptions

타입을 문자열로 변환할 때의 동작을 제어합니다.

preservedTypes
Array<string>
resolve하지 않고 이름 그대로 보존할 타입 목록. 예: ReactNode를 넣으면 내부 union으로 풀지 않고 "ReactNode"로 출력.
기본: React 공통 10개 (ReactNode, CSSProperties, ForwardedRef 등)
typeParameterMap
Record<string, string>
제네릭 타입 파라미터 이름을 다른 이름으로 치환. 예: { T: 'ElementType' }이면 T가 보일 때 ElementType으로 표시.
기본: {} (치환 안 함, T는 T로 표시)
maxDepth
number
타입 재귀 해석 깊이 제한. 깊이를 초과하면 import 경로만 정리한 원본 텍스트로 폴백.
기본: 2

ExtractorOptions

Props 추출 시 특수 처리 규칙을 제어합니다.

rawTypeProps
Array<string>
Resolver를 거치지 않고 cleanTypeText()로만 정리할 prop 이름들. 반응형 breakpoint prop처럼 원본 타입 텍스트를 유지하고 싶을 때 사용.
기본: []
complexAnnotationTypes
Array<string>
타입 annotation에 이 이름이 포함되면 resolve하지 않고 annotation 텍스트를 그대로 사용. 예: ComponentPropsWithoutRef<'input'>
기본: ['ComponentPropsWithoutRef', 'ComponentProps']

프리셋 비교

같은 코드를 옵션만 바꿔서 파싱했을 때 어떤 차이가 나는지 비교합니다.

기본 (옵션 없음)
new Parser(tsconfig)

// DataTable 결과:

onRowClick: (row: T) => void
vs
Montage 프리셋
new Parser(tsconfig, {
  resolver: {
    preservedTypes: [...기본, 'SxProp', 'ThemeColorsToken'],
    typeParameterMap: { T: 'ElementType' },
  },
  extractor: {
    rawTypeProps: ['xs','sm','md','lg','xl'],
  },
})

// DataTable 결과:
data: ElementType[]  // T → ElementType
onRowClick: (row: ElementType) => void
요점 — 기본값만으로도 범용 React 프로젝트에서 바로 동작합니다. 옵션은 프로젝트 전용 타입이나 특수 패턴이 있을 때만 건드리면 됩니다.

인식하는 컴포넌트 패턴

별도의 설정 없이 다음 패턴을 모두 자동 인식합니다.

패턴코드
Arrow function export const Button = ({ size = 'md' }: Props) => { }
Function declaration export function Button({ size }: Props) { }
forwardRef (타입 인자) forwardRef<HTMLDivElement, Props>((props, ref) => { })
forwardRef + as 캐스팅 forwardRef((...) => ...) as PolymorphicComponent<...>
memo export const Avatar = memo(({ src }: Props) => { })
Re-export export { Button } from './button'

출력 구조

ComponentInfo

{
  "name":     "Button",
  "filePath": "/src/components/button/index.tsx",
  "props":    [Prop, Prop, ...]
}

Prop

{
  "name":         "size",                              // 항상 존재
  "type":         "\"small\" | \"medium\" | \"large\"",   // 항상 존재
  "isOptional":   true,                               // 항상 존재
  "description":  "버튼 크기",                        // JSDoc이 있을 때만
  "defaultValue": "\"medium\""                        // 구조분해 기본값이 있을 때만
}
description은 타입 선언의 JSDoc에서, defaultValue은 함수 파라미터의 구조분해 기본값에서 추출됩니다. 두 곳 모두 없으면 해당 필드는 생략됩니다.

사용 예제 모음

1. 기본 — 전체 스캔

import { Parser } from './lib';

const parser = new Parser('./tsconfig.json');
const all = parser.getExportedItems();

// 원하는 파일만 필터
const filtered = all.filter(i => i.filePath.includes('/components/'));
const result = parser.parse(filtered);

2. 파일 하나만 파싱

const items = parser
  .getExportedItems()
  .filter(i => i.filePath === '/absolute/path/to/button/index.tsx');

const [button] = parser.parse(items);

3. Montage 디자인 시스템 프리셋

const parser = new Parser('./tsconfig.json', {
  resolver: {
    preservedTypes: [
      'ReactNode', 'CSSProperties', 'ForwardedRef',  // React 공통
      'SxProp', 'ThemeColorsToken', 'CSSInterpolation',  // Montage 전용
    ],
    typeParameterMap: { T: 'ElementType' },
  },
  extractor: {
    rawTypeProps: ['xs', 'sm', 'md', 'lg', 'xl'],  // 반응형 props
  },
});

4. MUI/Chakra 같은 외부 라이브러리 스타일

const parser = new Parser('./tsconfig.json', {
  resolver: {
    preservedTypes: [
      'ReactNode', 'CSSProperties',
      'SystemStyleObject', 'ThemeTypings',    // 프로젝트 전용
    ],
    maxDepth: 3,  // 깊은 제네릭도 풀기
  },
  extractor: {
    complexAnnotationTypes: [
      'ComponentPropsWithoutRef',
      'HTMLAttributes',
      'SVGAttributes',
    ],
  },
});

자주 묻는 질문

onClick 같은 HTML 이벤트가 안 나와요

의도된 동작입니다. @types/react에서 오는 기본 props는 자동 제외합니다. 컴포넌트가 직접 정의한 props만 추출하여 문서 노이즈를 줄입니다.

타입이 import("...").Something으로 나와요

maxDepth를 초과한 경우입니다. 값을 3이나 4로 올리면 더 깊이 풀어줍니다. 단, 너무 높이면 성능이 저하될 수 있습니다.

특정 prop 이름의 타입을 원본 그대로 보고 싶어요

extractor.rawTypeProps에 해당 prop 이름을 넣으면 Resolver를 거치지 않고 import 경로만 정리한 원본 텍스트를 사용합니다.

제네릭 T가 그대로 노출돼요

resolver.typeParameterMap에 { T: '원하는이름' }을 넣으면 치환됩니다. 비워두면 T 그대로 출력합니다.

새 컴포넌트를 추가하면 자동으로 인식되나요?

네. tsconfig.json의 include 범위 안에 있고, PascalCase로 export하면 자동 인식됩니다. getExportedItems() 이후 .filter()로 원하는 경로만 골라 쓰세요.
